# GMsFEM для рассеяния на проницаемых включениях

Реализация строит тонкое комплексное CG1 решение, локальные snapshot пространства и базисы Type 1/2, затем сравнивает GMsFEM с обычным МКЭ. Геометрия 24 круговых включений взята из исходных notebooks проекта. Подробные формулы и соглашения приведены в [методической документации](docs/method.md).

Это адаптация метода [статьи Kalachikova et al.](../references/10%20GMsFEM%20for%20scattering%20problem.pdf), [DOI](https://doi.org/10.1016/j.cam.2022.114977), к геометрии проекта. Исходные notebooks сохранены. Числа таблиц статьи не воспроизводятся буквально: авторские координаты, радиусы и сетки не опубликованы.

## Быстрый учебный вход

[Учебный маршрут на 60–90 минут](docs/learning_path.md) проводит от одного P1 элемента до snapshots, локального спектра, функций χ и глобальной проекции. В нем есть разобранный patch с реальными размерностями, два проверяемых набора чисел, короткие опыты и 12 вопросов с ответами. [Ревизия реализации](docs/audit.md) отделяет проверенные свойства от рисков обусловленности и ограничений физических выводов.

```bash
# Проверить сохраненные поля и все 28 строк ошибок без нового PDE solve:
docker compose exec -T dolfinx-complex python3 -m gmsfem.learning verify
# Решить малый опыт и раскрыть центральный patch в trace.json:
docker compose exec -T dolfinx-complex python3 -m gmsfem.learning trace --output /tmp/gmsfem-lesson
```

Перед командами запустите сервис, как описано ниже. `/tmp/gmsfem-lesson` находится в контейнере; для сохранения на хосте задайте каталог внутри `gmsfem/results/`. Снимок нового учебного опыта с версиями пакетов и хэшами исходников: [learning_trace.json](docs/learning_trace.json).

## Запуск в существующем Docker окружении

Все команды выполняются из корня репозитория. Используется существующий сервис `dolfinx-complex` из `compose.yaml`; дополнительных установок пакетов для этого workflow не требуется.

```bash
docker compose up -d dolfinx-complex
docker compose exec dolfinx-complex jupyter server list
```

Откройте выданную ссылку JupyterLab и [gmsfem/GMsFEM_scattering.ipynb](GMsFEM_scattering.ipynb). Выберите ядро **Python (DOLFINx Complex)**. Проверить тип PETSc можно отдельно:

```bash
docker compose exec -T dolfinx-complex python3 -c 'from petsc4py import PETSc; print(PETSc.ScalarType)'
```

Ожидается комплексный тип `numpy.complex128`. Модуль также проверяет комплексный PETSc при сборке. Расчеты выполняются последовательно: глобальная сборка использует DOLFINx, редукция и локальная линейная алгебра — SciPy. Не запускайте этот workflow через `mpirun`: распределенная нумерация и распределенные матрицы здесь не поддерживаются.

Notebook по умолчанию использует `CASE="notebook"`, \(k=1\), фоновый целевой размер \(h=0.04\), крупные сетки \(10\times10\) и \(20\times20\), оба типа базиса и \(M=1,2,4,6,8,12,16\) функций на крупную вершину. Полный запуск включает отдельное сравнение с более мелкой reference сеткой в конце.

## Командная строка

CLI запускается из корня репозитория через `python3 -m gmsfem.run`. По умолчанию выбраны полный профиль `demo` и материалы `notebook`; это не сокращенный smoke test.

```bash
docker compose exec -T dolfinx-complex python3 -m gmsfem.run --output gmsfem/results/notebook
```

Быстрый ознакомительный запуск:

```bash
docker compose exec -T dolfinx-complex python3 -m gmsfem.run --profile quick --output gmsfem/results/quick
```

Пример явного задания параметров и материалов первого примера статьи:

```bash
docker compose exec -T dolfinx-complex python3 -m gmsfem.run --profile demo --case paper_example1 --k 1 --h 0.04 --coarse 10 20 --modes 1 2 4 6 8 12 16 --types 1 2 --output gmsfem/results/paper_example1
```

| Параметр | Значение |
|---|---|
| `--profile quick` | Крупная сетка 4×4, \(h=0.1\), \(M=1,2,4\) |
| `--profile demo` | Крупные сетки 10×10 и 20×20, \(h=0.04\), \(M=1,2,4,6,8,12,16\) |
| `--profile paper` | Та же серия крупных сеток и мод, фоновый \(h=0.015\); название не означает точную репродукцию статьи |
| `--case` | `notebook`, `paper_example1`, `paper_example2`, `homogeneous` |
| `--k` | Положительное волновое число; по умолчанию 1 |
| `--h` | Переопределяет целевой фоновый размер тонких элементов |
| `--coarse` | Число квадратов вдоль каждой оси для каждой крупной сетки |
| `--modes` | Числа оставляемых мод на крупную вершину |
| `--types` | Один или оба типа локального оператора: `1`, `2` |
| `--direction` | Две компоненты единичного направления падающей волны; по умолчанию `1 0` |
| `--output` | Каталог результатов; без флага используется `gmsfem/results/<case>_k<k>` |
| `--no-reference` | Пропускает отдельный завершающий расчет МКЭ на сетке с целевым \(h/2\) |
| `--no-plots` | Пропускает PNG, сохраняя численные результаты |

Параметры `--h`, `--coarse`, `--modes` переопределяют значения профиля. Доступные аргументы также выводятся через `python3 -m gmsfem.run --help` внутри контейнера.

## Геометрия и материалы

[geo/scattering.geo](geo/scattering.geo) задает CAD геометрию, границы включений и крупные разделительные линии. [geo/reference.geo](geo/reference.geo) включает тот же источник для независимой более мелкой сетки. Это обычные читаемые `.geo` файлы; расчетная генерация использует их через Gmsh Python API.

Физические группы материалов назначаются функцией `geometry.py` по внутренним точкам поверхностей после BooleanFragments. Поэтому один лишь самостоятельный импорт `.geo` в Gmsh не заменяет Python pipeline для получения всех расчетных материальных тегов.

Значение `h` управляет фоновым размером элементов. Вблизи окружностей применяется локальное уточнение с учетом кривизны и разрешением не менее 32 точек на полную окружность; минимальный размер не зажат фоновым `h`. Это существенно для самых маленьких включений радиуса 0.02. Reference генерируется заново с фоновым размером `h/2`; это независимая сетка на той же CAD геометрии, а не автоматически вложенное измельчение.

Для всех крупных сеток одной серии используется **одна** основная тонкая сетка. CAD разбивается по `lcm(coarse_grids)`; например, сетка согласована одновременно с крупными 10×10 и 20×20. Это позволяет сравнивать редукции с одним тонким reference, не смешивая их ошибки с изменением тонкой сетки. Сначала выполняется вся серия GMsFEM; независимый более мелкий МКЭ рассчитывается последним.

Во всех presets принимается \(A=\alpha I\), фон \((\alpha,n)=(1,1)\). Preset `notebook` сохраняет материалы исходных notebooks: во всех включениях \((0.2,10)\). Для `paper_example1` большие окружности получают \((3,0.8)\), средние \((5,0.4)\), малые \((10,0.2)\), по визуальному сопоставлению цветов Fig. 7 статьи. В `paper_example2` все включения имеют \((10,0.2)\). Preset `homogeneous` убирает материальный контраст для проверки нулевого рассеяния.

## Что изменено относительно исходных notebooks

Метод статьи использует непрерывный линейный базис: здесь выбран CG1. Исходный CG notebook задает степень 2, а DG notebook использует разрывное пространство и штрафные интерфейсные члены. Поэтому совпадение узловых решений с этими notebooks не является критерием корректности GMsFEM реализации. Глобальная связь базисов здесь непрерывная; DG вариант не является реализованным методом статьи.

Исправлена правая часть при скачках DG0 коэффициента: используется слабая контрастная форма

\[
F(v)=\int(1-\alpha)\nabla u^i\cdot\nabla\bar v
+k^2\int(n-1)u^i\bar v.
\]

Она включает действие материальных интерфейсов. Вычисление `div((1-A)*grad(u_i))` только внутри элементов, как в исходных notebooks, этот вклад теряет. Несогласованность знака между сильной и слабой формами самой статьи разобрана в [docs/method.md](docs/method.md).

Решается рассеянное поле \(u^s\); полное восстанавливается как \(u^i+u^s\). Для ошибок сохранены и знаменатель multiscale из формулы статьи, и обычный знаменатель fine/reference. Смешанная картинка `paper_mixed` явно показывает \(Re(u^s),Im(u^s),|u^i+u^s|\), как исходный DG notebook. Такое оформление правдоподобно объясняет Fig. 8, однако не устанавливает, какое поле авторы использовали для каждой метрики таблиц.

## Результаты

Сохраненные серии находятся в [results/notebook/report.md](results/notebook/report.md) и [results/paper_example1/report.md](results/paper_example1/report.md). Актуальные размеры систем, ошибки и времена следует смотреть в отчете и `summary.json` конкретного запуска.

| Файл | Содержимое |
|---|---|
| `report.md` | Читаемый отчет с конфигурацией, результатами и ограничениями сравнения |
| `errors.csv` | Ошибки GMsFEM относительно тонкого МКЭ, параметры и диагностика каждой комбинации |
| `reference_errors.csv` | При включенном reference: сравнение с независимым более мелким МКЭ |
| `summary.json` | Конфигурация серии, диагностика, времена, сведения о reference |
| `fields.npz` | Координаты, треугольники, материальные данные и комплексные поля |
| `spectra.npz` | Локальные собственные значения для крупных сеток и типов базиса |
| `meshes.png`, `basis.png`, `convergence.png` | Сетки, локальные базисы и графики ошибок |
| `fields_total.png`, `fields_scattered.png` | Явно разделенные полное и рассеянное поля |
| `reference_comparison.png` | При включенном reference: отдельное сравнение полей и сеток |

Дополнительные PNG, включая смешанное представление, описываются своими подписями. Не следует сравнивать численные ошибки разных каталогов, не проверив `case`, `k`, сетку, поле и знаменатель нормы. Малый residual coarse системы подтверждает решение проекции, но сам по себе не доказывает малую ошибку относительно тонкого МКЭ.

## Карта исходного кода

Поток данных: `geometry.py → fem.py → offline.py → metrics.py → experiment.py → plotting.py → run.py`.

| Модуль | Основные функции и данные |
|---|---|
| [geometry.py](geometry.py) | `inclusion_circles()`, `generate_mesh()`; CAD, материальные группы и кэш сеток |
| [fem.py](fem.py) | `FineProblem`, `assemble_problem()`, `solve_fine()`, `local_matrices()`, `coarse_membership()`, `solve_dirichlet()` |
| [offline.py](offline.py) | `OfflineSpace`, `build_offline_space()`, `solve_reduced()`; snapshots, спектр, \(\chi_p\), проекция |
| [metrics.py](metrics.py) | `relative_errors()`, `P1Evaluator`, `errors_on_reference()`; интегральные нормы и перенос между сетками |
| [experiment.py](experiment.py) | `run_study()`, `compare_refined()`, `save_study()`; серия и сохранение результатов |
| [plotting.py](plotting.py) | `plot_meshes()`, `plot_basis()`, `plot_fields()`, `plot_convergence()`, `plot_refined_comparison()` |
| [run.py](run.py) | `main()`; CLI и параметры профилей |
| [learning.py](learning.py) | `verify_saved()`, `trace_study()`; пересчет сохраненных метрик и учебная трассировка patch |

В `OfflineSpace.P` базисные функции записаны **столбцами** в тонкой глобальной нумерации, группами по крупным вершинам. `prolongation(M)` выбирает первые `M` мод каждой вершины. Coarse оператор равен \(P^HA_hP\), а восстановление — \(PU_H\). Для спектральной задачи выбираются наименьшие собственные значения, масса имеет вес \(\alpha\). Type 2 функции \(\chi_p\) не нормируются делением на сумму.

## Проверки

Восемь тестов в [tests/test_numerics.py](tests/test_numerics.py) проверяют физические и алгебраические свойства:

1. Площадь области и включений, 24 связные компоненты, согласованность крупных ребер и внешнюю boundary mass.
2. Локальные P1 массы с весами \(n\) и \(\alpha\) против независимой глобальной UFL сборки.
3. Знак и интерфейсный RHS через независимую идентичность полного поля с аналитической падающей волной.
4. Отсутствие рассеянной волны при нулевом контрасте.
5. Спектры, residual snapshots и eigenproblems, следы \(\chi_p\), support базисов и константу Type 1.
6. Квадратурные ошибки против точной массовой нормы, фазовый сдвиг и аналитическую добавку падающей волны.
7. Перенос комплексного аффинного поля на независимую reference сетку.
8. Обогащение на проверочном случае и независимо вычисленный галеркинский residual.

Еще два теста в [tests/test_learning.py](tests/test_learning.py) пересчитывают обе сохраненные серии из массивов, сверяют CSV с JSON, проверяют точную P1 норму комплексной ошибки и обнаружение намеренно поврежденной метрики. Эта проверка артефактов не заменяет повторную сборку оператора и решение PDE.

Запуск из корня проекта:

```bash
docker compose exec -T dolfinx-complex python3 -m unittest discover -s gmsfem/tests -v
```

Проверка уменьшения ошибки при обогащении относится к тестовому случаю; она не является доказательством монотонности любой L2 метрики для неопределенной задачи Гельмгольца.
