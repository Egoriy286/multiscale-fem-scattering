# Численная ревизия GMsFEM

Ревизия выполнена 2026-11-08 по текущим `fem.py`, `offline.py`, `metrics.py`, `experiment.py`, сохраненным сериям и новым расчетам. Реализация содержит согласованную цепочку «тонкий CG1 → локальные Dirichlet snapshots → спектр → χ → Galerkin projection». В проверенных случаях явных ошибок основных операторов не обнаружено. Ниже указаны проверенные свойства, исправление отчетов и границы выводов. Это ревизия программной реализации, а не доказательство сходимости метода.

## Проверенная математическая цепочка

| Узел метода | Что фактически делает код | Свидетельство |
|---|---|---|
| Поле и RHS | Решает $u^s$, добавляет $u^i$ для total; контрастная слабая форма учитывает интерфейсы DG0 | Независимый тест тождества полного поля с аналитической волной, наклонным направлением и $k=1.3$ |
| Глобальный оператор | $K-k^2M_n-ikC$, где `B=C` без $k$; Robin только на внешних facets | Независимая локальная P1/UFL сборка, площадь внешней boundary mass, homogeneous test |
| Геометрия | Материальные включения заполнены; fine-треугольники не пересекают coarse-ребра | Площадь 16, 24 связных включения, площади трех радиусов и проверка пересечений |
| Snapshot-системы | Все граничные дельты; Type 1 $K$, Type 2 $K-k^2M_n$; матрицы собираются из элементов patch | Внутренние backward errors, граничные следы, прямой учебный trace |
| Локальный спектр | $(\Psi^TK\Psi,\Psi^TS_\alpha\Psi)$ для обоих типов; сохраняются наименьшие значения | Остатки eigenproblem, порядок и конечность значений, константа Type 1 |
| Сшивка | Ячеечные χ с Q1-следами; P1 интерполянт узлового произведения | Совпадение интерфейсных следов, support и нулевой след на внутренних границах patch |
| Online | `P.conjugate().T @ A_h @ P`, без использования fine-solution при построении базиса и solve | Независимый coarse Galerkin residual и просмотр потока данных |
| Метрики | Интегральные комплексные/Re/Im/модульные нормы; оба знаменателя; analytic incident в квадратуре | Точная P1 масса, чистый фазовый сдвиг, аналитический интеграл incident; пересчет файлов |
| Отдельная fine-reference | P1 перенос в физические точки независимой сетки, не nearest-neighbour | Комплексное аффинное поле воспроизводится с точностью round-off |

Формулы и соглашения подробнее приведены в [method.md](method.md). Сравнение относится к адаптации статьи Kalachikova et al. к геометрии проекта. Точный знак RHS здесь выведен из уравнения полного поля; неоднозначность статьи и несогласованность полей на ее рисунке документированы отдельно.

## Что исправлено при ревизии

CLI раньше записывал `report.md` **до** генерации PNG. Генератор отчета добавляет ссылки только на уже существующие рисунки, поэтому свежий выходной каталог получал численные таблицы без ссылок на только что созданные изображения. Теперь после построения рисунков обновляется только Markdown-отчет. Численные артефакты сохраняются заранее, поэтому отказ визуализации не теряет готовый результат. Время вычислений и состав математических операторов от этого не меняются.

Повторный CLI-запуск удаляет только известные ему рисунки до сохранения нового отчёта; `--no-plots` поэтому не подхватывает картинки прежнего опыта. При отсутствии reference удаляются его старые CSV и PNG. Пользовательские файлы с другими именами сохраняются; это проверено отдельным regression test.

Также убрана фиксированная фраза «обе крупные сетки и оба типа», неверная для запусков с одной сеткой или `--types 1`. Отчет говорит о всех вариантах фактической серии. Приведенная ранее в `method.md` формулировка о диагностике Type 2 резонанса уточнена: текущие residual-проверки не являются оценкой обусловленности.

Добавлен [learning.py](../learning.py): `verify` сверяет CSV/JSON, формы массивов, число DOF, порядок спектров, все 24 метрики каждой строки и точную P1 норму комплексной разности; `trace` строит новый малый опыт существующими production-функциями и показывает один patch. Проверка сохраненных массивов не пересчитывает $A_h$ и `P`: они не сохраняются в NPZ.

## Подтвержденные результаты

Базовые восемь научных тестов прошли в DOLFINx Complex. Учебный опыт `notebook`, $k=1$, $h=0.1$, $4\times4$, $M=1,2,4$ рассчитан заново; его размеры, eigenvalues, residual и ошибки записаны в [learning_trace.json](learning_trace.json). У него нет отдельного refined-reference; он предназначен для изучения редукции на фиксированной fine-сетке.

Обе сохраненные большие серии проверены по полям: по 28 строк, 17549 DOF, 34696 треугольников. Пересчитанные нормы согласуются с JSON/CSV с точностью round-off. `source_sha256` показывает изменение `run.py` и `experiment.py` после исходного запуска: это исправления генерации отчета. Старые серии не выдаются за заново рассчитанные после изменения исходников.

Полезный контрпример чрезмерной интерпретации residual: у нового quick-опыта Type 2, $M=1$ Galerkin residual $8.51\cdot10^{-15}$, но комплексная ошибка полного поля относительно fine — **12.493186%**. При $M=4$ ошибка **4.670786%** и residual $1.51\cdot10^{-14}$. Малый residual подтверждает решение проекции, а не достаточность пространства. У Type 1 при $M=1$ ошибка **12.476545%**: Type 2 не обязан быть лучше при каждом $M$.

## Остающиеся численные риски

1. **Близость локального Type 2 резонанса.** `splu` сообщает об отказе факторизации, проверка backward error ловит плохо решенную систему. Но почти вырожденная $K_{II}-k^2M_{II}$ может иметь малый residual и очень чувствительное решение. Число обусловленности, расстояние до локального Dirichlet-спектра и оценка forward error автоматически не вычисляются. Новые большие $k$ требуют отдельного исследования.
2. **Глобальная линейная зависимость/обусловленность базиса.** Ненулевые столбцы `P` нормируются по $L^2$, но не ортогонализуются глобально. Ненулевые нормы и `N_H<N_h` не доказывают полный ранг. Отказ coarse LU проверяется; надежной оценки глобального ранга/обусловленности сейчас нет. Рост $M$ может повышать чувствительность.
3. **Helmholtz не является coercive elliptic projection.** Увеличение вложенного пространства не гарантирует монотонность всех $L^2$-ошибок. Обогащение проверено для конкретного теста/серии; общей оценки ошибки по первому отброшенному $\lambda$ в реализации нет.
4. **Фиксированная квадратура.** RHS использует степень 6, метрики — семиточечную степень 5. Для P1 комплексной разности массовая норма точна; для аналитической экспоненты и разности модулей эти правила приближенны. Текущие тесты проверяют невысокие $k$; автоматического повышения степени по $kh$ нет.
5. **Тонкая дискретизация и внешнее ABC.** Малые multiscale/fine ошибки не подтверждают точность исходного FEM. Независимая сетка $h/2$ исследует чувствительность дискретизации и полигонализации кругов, но не доказывает сходимость физической внешней задачи. Расширение области/PML и convergence study по внешней границе не выполнены.
6. **Предел snapshot-пространства.** Содержатся локальные однородные Dirichlet-продолжения, а не все fine-функции. Нельзя автоматически заключать, что сохранение всех snapshots дает точное глобальное fine-решение для произвольной объемной нагрузки. Алгоритм не содержит специальных source-correctors или bubble enrichment.
7. **Стоимость редукции.** `solve_seconds` не включает offline и projection. Текущий offline-базис перестраивается при новом `run_study`; Type 2 зависит от $k$. Малое online-время и число DOF не доказывают ускорения полного единичного расчета. Последовательный SciPy backend не поддерживает MPI-distributed solve.
8. **Происхождение данных.** Числа `paper_example1/2` задают материалы на 24 notebook-включениях. Координаты и сетки статьи не воспроизведены; смешанное представление полей — отмеченная интерпретация рисунка. Это нельзя называть точной репликацией статьи.

Эти пункты ограничивают допустимые выводы, а не устанавливают дефект результата при проверенных параметрах. Порог residual не заменяет исследование конкретного риска.

## Как повторить ревизию

```bash
docker compose exec -T dolfinx-complex python3 -m unittest discover -s gmsfem/tests -v
docker compose exec -T dolfinx-complex python3 -m gmsfem.learning verify
docker compose exec -T dolfinx-complex python3 -m gmsfem.learning verify gmsfem/results/paper_example1
docker compose exec -T dolfinx-complex python3 -m gmsfem.learning trace --output /tmp/gmsfem-audit
```

Для публикационного вывода дополнительно нужны серии по fine-сетке, внешней границе и частоте с одинаковыми материалами/полями/нормами, анализ резонансов и полный accounting времени. Они здесь не объявляются выполненными. Для сохранения истории экспериментов используйте отдельный выходной каталог. CLI очищает собственные PNG при повторном запуске, а `save_study` удаляет старые reference CSV/PNG при отсутствии нового reference. При самостоятельном вызове `save_study` обычные графики контролирует вызывающий код.
