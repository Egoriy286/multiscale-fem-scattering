# Inference на других FEM-сетках

[Cross-mesh-inference.ipynb](../notebooks/Cross-mesh-inference.ipynb) проверяет сохранённые low-band и high-band randomized SVD-SNO модели на других сетках той же области и той же физической среды 0. Веса, normalization и исходные POD-базисы фиксированы; коэффициенты сеть заново предсказывает для каждого запроса `(k,θ)`. Для одного запроса source- и target-представления используют одинаковые коэффициенты, нового обучения и подгонки по target FEM-полям нет. Notebook полностью выполнен в новом kernel; ниже приведены фактические результаты сохранённого запуска.

## Что переносится

Source-сетка обучения: h=0.1, coarse partition 4×4, 3221 узел. Среда, круги, контрасты A,n, частотные полосы и поглощающее граничное условие сохраняются. Проверяются:

| Target | Что меняется |
| --- | --- |
| h=0.2, coarse partition 4×4 | Более грубая FEM-сетка |
| h=0.1, coarse partition 3×3 | Другая вспомогательная разбивка и triangulation при той же физической геометрии |
| h=0.05, coarse partition 4×4 | Более мелкая FEM-сетка |
| Перестановка узлов source-сетки | Только индексация, sanity check порядка DOF |

Шаг h — параметр генератора, а не утверждение об одинаковом размере всех треугольников. Фактические counts, connectivity и размер элементов проверяются по готовым сеткам. Изменение coarse partition здесь не меняет форму физических включений и не означает новый материал.

Для каждой полосы выбираются первая, средняя и последняя по k удержанные частотные группы. Внутри группы берутся направления j=0 и j=2 после сортировки восьми углов: шесть запросов `(k,θ)` на полосу. Для coarse/retriangulated/fine target reference вычисляется независимым FEM-решением на соответствующей сетке с тем же физическим материалом. В sanity check перестановки reference получается той же перестановкой source FEM, без нового решения. Это малый тест выбранных случаев, а не замена полной test-оценке.

## Формула переноса

Сохранённая SVD-модель предсказывает коэффициенты c для исходного P1-представления

\[
 \hat u_s=\mu_s+\Phi_s c.
\]

Для отдельных вещественного и мнимого базисов формула применяется к обоим каналам и затем собирается комплексное поле. Пусть T_{s→t} — матрица вычисления source P1-функций в target-узлах. Тогда

\[
 \mu_t=T_{s\to t}\mu_s,\qquad
 \Phi_t=T_{s\to t}\Phi_s,\qquad
 \hat u_t=\mu_t+\Phi_t c.
\]

Для каждого запроса используются те же предсказанные коэффициенты c, что и на source-сетке, включая сохранённое обратное масштабирование; между запросами c меняются. Линейность даёт

\[
 \hat u_t=T_{s\to t}(\mu_s+\Phi_s c)=T_{s\to t}\hat u_s.
\]

Поэтому перенос mean/modes и перенос готового source prediction совпадают с точностью округления. Проверка этого равенства называется здесь commutation check; её малая ошибка подтверждает согласованность реализации, а не точность решения PDE.

`P1Transfer` использует фактический source triangle connectivity, находит содержащий треугольник и записывает его три барицентрических веса в sparse CSR-матрицу. Это вычисление уже выученных P1-функций, а не новая Delaunay-триангуляция массива координат. Точки за пределами source-сетки или внутри её отверстий вызывают ошибку. При поиске треугольника допускается лишь погрешность у фактического граничного сегмента не более `1e-12·max(1, размер bounding box)`; барицентрические веса вычисляются в исходных координатах target-точки. Эта обработка округления границы не разрешает перенос на внешние точки на физически значимом расстоянии. Порядок узлов и индексы connectivity должны изменяться согласованно.

Обратный оператор T_{t→s} строится отдельно. На разных triangulations он в общем случае не является обратной матрицей к T_{s→t}; roundtrip может иметь ненулевую ошибку даже при правильной реализации. Перестановка индексов той же сетки, напротив, должна сохранять поле с точностью округления.

## Входные поля и API

Привязку к target-сетке выполняет `Predictor.on_mesh(coordinates, triangles=None)`, возвращающий `MeshPredictor`. Для текущей фиксированной среды достаточно:

```python
mapped = predictor.on_mesh(target_coordinates, target_triangles)
u_target = mapped.predict_static(theta, k0)
```

Для входных полей в target-node order используется `mapped.predict(A_target, n_target, theta, k0)`. Он переносит A,n обратно на source-сетку, поэтому требует target triangles. `predict_static` допускает scalar или одномерные broadcast-совместимые массивы theta/k0 и проверяет нулевые ранги обоих входных базисов. В текущем исследовании вызывается именно `predict_static`. Полный эксперимент реализован в `mesh_study.run_cross_mesh_study(...)`; конкретные вызовы приведены в notebook.

Если входные POD-базисы A,n имеют ненулевой ранг, target-входы сначала вычисляются в source-узлах оператором T_{t→s}, после чего применяется сохранённое source encoding. Перенос узловых коэффициентов через интерфейсы материалов может вносить собственную ошибку; он не заменяет точные DG0 материалы в FEM-решателе.

У текущих статичных моделей оба входных ранга равны нулю. Сеть зависит только от `(cos θ,sin θ,k)`; material mean и output modes уже относятся к фиксированной среде. `predict_static` использует это свойство. Передача других A,n не превращает такие модели в оператор по новым материалам; текущий эксперимент сохраняет исходную среду 0.

## Ошибки, которые нужно читать отдельно

Обозначим u_s — source FEM reference, u_t — независимо решённый target FEM reference, \hat u_s — source prediction и \hat u_t=T_{s→t}\hat u_s. Все ошибки в target-узлах измеряются в consistent P1 FEM L2 target-сетки M_t:

\[
 e(v,w;M)=\frac{\sqrt{(v-w)^*M(v-w)}}
 {\sqrt{w^*Mw}},\qquad \|w\|_M>0.
\]

| Строка результата | Смысл |
| --- | --- |
| Model vs target FEM: e(\hat u_t,u_t;M_t) | Итоговая ошибка перенесённой модели относительно target reference |
| Transferred source FEM vs target FEM: e(T_{s→t}u_s,u_t;M_t) | Различие дискретизаций вместе с ошибкой переноса source reference |
| Model vs transferred source FEM: e(\hat u_t,T_{s→t}u_s;M_t) | Ошибка модели относительно её исходного дискретного эталона после переноса |
| Roundtrip | e(T_{t→s}T_{s→t}u_s,u_s;M_s), изменение source FEM после двух переносов |
| Commutation | e(\hat u_t,T_{s→t}\hat u_s;M_t) и абсолютная L2 разница двух способов переноса prediction |

В коде нет epsilon в знаменателе: если reference norm и numerator равны нулю, ошибка равна 0; если reference norm равна нулю, а numerator положителен, результат +∞. Roundtrip оценивается именно для source FEM reference в M_s. Дополнительно сохраняется исходная ошибка source model vs source FEM для тех же шести запросов. Относительные ошибки разных строк имеют разные reference denominators; складывать их проценты как точное разложение итоговой ошибки нельзя. Полезно сохранять и абсолютные L2 ошибки, особенно при малом рассеянном поле.

Уменьшение target h не добавило в frozen source-базис недостающие компоненты. Другая triangulation с 3274 узлами дала high-band ошибку 10.8646%, но это не доказывает mesh-independent learning: mean/modes только вычислены на новых узлах. Модель остаётся обученной к исходной P1-дискретизации.

Перестановка source-узлов сохранила reference с mean relative difference около 6.28×10⁻¹⁸ low и 7.87×10⁻¹⁸ high; model error совпала с исходной ошибкой выбранных запросов. Эти проверки подтверждают корректность переноса и порядка DOF, не точность непрерывной PDE.

## Что доказывает такой эксперимент

Модель может выдавать значения на новых FEM-узлах благодаря переносу своего исходного P1-базиса. Этот механизм эквивалентен интерполяции старого prediction и не подтверждает независимость выученного оператора от дискретизации. Более мелкая target-сетка сама по себе не добавляет в frozen source-базис новые мелкомасштабные компоненты и не восстанавливает физику, отсутствовавшую в обучающих метках.

Ранее измеренные mean test errors моделей относятся к source-сетке обучения. Их нельзя подписывать как точность на новой сетке. Для высокой полосы ранее наблюдалась заметная разница между FEM-решениями на исходной и уточнённой сетках; она может существенно влиять на сравнение с target reference. Численную величину этого вклада для выбранных шести запросов определяют только строки текущего эксперимента.

Это проверка других triangulations при неизменных области и материале. Новая геометрия включений, новая область или новые материалы требуют отдельного исследования и не покрываются этим notebook.

## Сохраняемые сведения

Эксперимент сохраняет `per_case.csv` (band, mesh, sample/frequency IDs, k,θ, counts DOF, все ошибки и времена), `summary.json` (mean/max по шести запросам каждой полосы/сетки и metadata), `mesh_info.json` (параметры и counts сеток), `fields.npz` (все шесть выбранных reference/prediction/transferred-source полей и параметры запросов для каждой полосы/сетки). Сохранённые поля позволяют перепроверить target FEM L2 ошибки всей сводки, а не только отдельной иллюстрации.

Metadata сохраняет source/target coordinates/connectivity hashes и dtypes, все выбранные запросы, coverage, максимальное число ненулевых элементов строки и row-sum defect для forward/reverse transfers. Явно записываются `training_epochs=0` и `refit=false`.

SHA256 checkpoint проверяется до и после эксперимента; при изменении файла запуск завершается ошибкой. Собственные `.msh` target-сеток сохраняются в `meshes/`. Времена разделяют загрузку checkpoint, setup source solver, построение transfers, перенос mean/modes, source/target FEM solve и inference; batch setup/inference значения делятся на число выбранных запросов. Эти amortized batch значения не являются независимыми замерами single-query latency.

Новых эпох обучения и fit target-полей нет. Фактические ошибки и времена этого запуска сохранены в перечисленных CSV/JSON; hash-проверки подтверждают неизменность checkpoint.
