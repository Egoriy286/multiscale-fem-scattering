# Другие координаты включений и коэффициенты A,n

Этот протокол описывает проверку сохранённых frozen randomized SVD-SNO моделей на средах с изменёнными **координатами центров включений**, а также отдельными изменениями A,n. Low-band и high-band модели не переобучаются. В каждом случае строится соответствующая физическая сетка и независимо решается target FEM-задача. Численные результаты будут добавлены после фактического запуска.

Это проверка ограничения текущих моделей одной фиксированной среды: у них входные POD-ранги A,n равны нулю. При одинаковых `(k,θ)` сеть не получает информацию о новых включениях или коэффициентах. Значения на новой сетке получаются вычислением исходного предсказанного P1-поля в её узлах; сама смена сетки не делает предсказание зависимым от новой среды.

## Случаи эксперимента

Внешняя область, радиусы кругов, частотные полосы и граничное условие сохраняются. Активность и соответствие материалов кругам сохраняются по `circle_id`; коэффициенты внутри активных кругов относятся к исходной фиксированной среде 0, если не указано иное.

| Случай | Координаты центров | A внутри активных включений | n внутри активных включений |
| --- | --- | --- | --- |
| Baseline | Исходные | Исходные | Исходные |
| Translation | Всем центрам добавлено (0.18,−0.12) | Исходные | Исходные |
| Safe jitter | Воспроизводимые отдельные смещения центров | Исходные | Исходные |
| A-only | Исходные | 1.5−A_original | Исходные |
| n-only | Исходные | Исходные | 4.5−n_original |
| Translation + both | Всем центрам добавлено (0.18,−0.12) | 1.5−A_original | 4.5−n_original |

Фон A=n=1 сохраняется. Для A-only отражение `A_new=1.5−A_old` сохраняет исходный диапазон [0.6,0.9]; для n-only `n_new=4.5−n_old` сохраняет [1.5,3]. Combined case использует те же reflected значения. Фон и неактивные круги остаются A=n=1. Изменение контрастов происходит внутри знакомых амплитудных диапазонов, чтобы отделить чувствительность к среде от амплитудной экстраполяции. Jitter должен сохранять непересечение кругов и нахождение внутри области; конкретные реализованные смещения записываются в `cases.json`. Ни угол падения, ни k не заменяют координаты центров в этой постановке.

Для translation/jitter выполняется **физическое перестроение сетки по новым окружностям**. Это не перестановка индексов узлов и не перенос прежних DG0 массивов на ячейки с теми же номерами. Target DG0 A,n назначаются по идентичности круга, чтобы скачки материалов совпадали с фактическими target-интерфейсами. Случаи A-only/n-only выделяют изменение коэффициентов при сохранённых центрах. Combined case меняет и центры, и оба коэффициента.

## Запросы и независимый reference

В каждой частотной полосе используются три held-out частотные группы по два направления, всего шесть запросов `(k,θ)` на случай. Выбранные sample/frequency IDs, k и углы сохраняются, чтобы baseline и изменённые среды сравнивались на одних и тех же волновых параметрах. Эти частоты удержаны при первоначальном обучении модели; изменённые среды не входили в её статичный train dataset.

Для каждого target-case FEM решается заново с его центрами, радиусами, точными DG0 коэффициентами и тем же incident wave. Эталон — дискретное FEM-решение на этой сетке; его нельзя называть точным непрерывным решением. Исходная модель и baseline reference не заменяют этот solve.

## Почему frozen модель не реагирует на новую среду

Текущий encoder имеет вид

\[
 z(k,\theta)=(\cos\theta,\sin\theta,\widetilde k),\qquad
 c=N_\vartheta(z),\qquad
 \hat u_s=\mu_s+\Phi_s c.
\]

Входные коэффициенты A,n отсутствуют из-за нулевых рангов центрированных статичных полей. Для каждого запроса сеть вычисляет свои c, но смена центров или A,n при том же запросе не меняет эти коэффициенты. Сохранены weights, normalization и source POD-базисы; refit target-полей отсутствует.

Если T_{s→t} вычисляет source P1-поле в узлах новой сетки, выдаваемый результат равен

\[
 \hat u_t=(T_{s\to t}\mu_s)+(T_{s\to t}\Phi_s)c
          =T_{s\to t}\hat u_s.
\]

Разные target-координаты могут дать другие массивы узловых значений, поскольку поле запрашивается в других точках. Это пространственная интерполяция одного source prediction, а не реакция сети на новую среду. На общих физических точках frozen предсказание для одинаковых k,θ остаётся тем же с точностью округления.

Ненулевая конечная ошибка относительно изменённого FEM-reference сама по себе не доказывает material/geometry generalization. Даже малую ошибку нужно сопоставить с изменением самого эталонного поля и неспособностью модели менять ответ по среде. Baseline нужен для исходного уровня ошибки на той же выборке, а не для переноса опубликованной метрики полного test на шесть запросов.

## Метрики и контроль корректности

Основная метрика — consistent P1 FEM L2 комплексного рассеянного поля на target-сетке. Относительная ошибка model vs target FEM использует норму соответствующего target reference в знаменателе. Для почти нулевых полей дополнительно нужна абсолютная ошибка и явная обработка нулевой нормы.

Следует раздельно читать:

- ошибку frozen модели относительно нового независимо решённого target FEM;
- baseline-ошибку на тех же k,θ;
- изменение target FEM относительно перенесённого baseline reference, если оно вычисляется: оно может включать физическое изменение **и** различие дискретизаций/переноса;
- равенство target prediction перенесённому source prediction и неизменность input ranks;
- неизменность checkpoints, число новых training epochs=0 и refit=false.

Различия процентов нельзя складывать как точное разложение ошибки. На разных target triangulations сравнение массивов без явного переноса также некорректно. Отдельный [cross-mesh протокол](cross_mesh_inference.md) объясняет перенос P1-базиса и discretization gap при той же физической среде; здесь добавляется реальное изменение центров/материалов.

## Артефакты и завершение проверки

`cases.json` должен сохранять для каждого случая фактические центры, радиусы и A,n с идентичностью кругов. Для воспроизведения также нужны параметры сеток, coordinates/connectivity и checkpoint hashes, выбранные запросы, per-case ошибки, reference/prediction поля, dtype и времена независимых FEM solves. Названия итоговых численных файлов и значения будут приведены после успешного выполнения notebook.

До этого запуска результаты и время не прогнозируются. Эксперимент не включает обучение новых моделей. Он проверяет существующие frozen модели в новой геометрии включений и документирует их фактическое ограничение по входному представлению. Ошибка высокочастотного FEM-reference по-прежнему требует собственной mesh-refinement проверки; смена центров не устраняет ошибку дискретизации.
