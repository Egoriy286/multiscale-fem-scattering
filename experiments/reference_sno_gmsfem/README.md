# SNO и GMsFEM на эталонной среде МКЭ

Самостоятельный эксперимент от 9 ноября 2026 года. Данные, модели, исходный код и результаты находятся в этой новой директории. Существующие серии `neural_operator/data`, `neural_operator/runs` и `gmsfem/results` используются только как источники кода и эталонов и не перезаписываются.

Цель — обучить SVD-SNO v2 на **той же эталонной среде МКЭ**, что использована в сохранённом эксперименте GMsFEM, и сравнить ошибки на одинаковых тестовых задачах в двух диапазонах волнового числа: **K = [0.1, 2]** и **K = [2, 4]**. Здесь K — диапазон скалярного волнового числа k; множитель 2π не добавляется.

Фактические результаты: [results/REPORT.md](results/REPORT.md), [полная таблица](results/comparison.csv), [машиночитаемый отчёт](results/comparison.json). Устройство модели и все гиперпараметры подробно разобраны в [MODEL.md](MODEL.md).

**Решения и разности на картах:** [сравнение с переключателями](results/visuals/index.html) · [объяснение рисунков и входных параметров](results/visuals/README.md). Здесь показаны реальные поля МКЭ/SNO/GMsFEM для четырёх test-задач, точные α/n, сетка, падающая волна и направление, а также знаковые и комплексные ошибки. Эти карты дополняют средние ошибки ниже.

**Обучение и сравнение выполнены.** Создано 2568 FEM-полей на сохранённой reference-сетке; обе SNO обучены по 500 эпох. Основной итог — средняя комплексная L²-ошибка **полного поля** к reference FEM:

| Тестовый диапазон | SNO, % | Лучший GMsFEM, % | Точнее в этом запуске |
|---|---:|---:|---|
| [0.1,2], 216 полей | 0.3325 | 0.2534 | GMsFEM |
| [2,4], 208 полей | 2.6968 | 6.3494 | Отдельно обученная SNO high |

Лучший GMsFEM в обоих случаях — **20×20, Type 2, 16 мод**. Обе модели обучены внутри своих диапазонов. Замороженная low-модель на k>2 даёт **131.8231%** средней ошибки полного поля: успешного переноса без нового обучения здесь нет. При единственной контрольной точке k=1,θ=0 SNO даёт 0.1542%, GMsFEM — 0.1778%; это не заменяет сравнение по всему диапазону.

Исходная таблица GMsFEM воспроизведена: все 732 численных значения совпали точно. Пройдены 57 тестов нового workflow/операторов/FEM-loss и 11 тестов GMsFEM. Обе модели повторно загружены; проверенные предсказания совпали с сохранёнными. [Проверка данных](results/dataset_verification.json), [проверка checkpoints](results/checkpoint_verification.json), [контроль полноты и одинаковых test-задач](results/validation.json).

## Какая задача решается

В области Ω = [−2,2]² расположены все **24 включения** исходной геометрии GMsFEM. Их центры и радиусы берутся из `gmsfem.geometry.inclusion_circles()`, единственный CAD-источник — `gmsfem/geo/scattering.geo`. Включения заполнены материалом, а не вырезаны из области.

| Материал | α в A = αI | n |
|---|---:|---:|
| Фон | 1 | 1 |
| Каждое из 24 включений | 0.2 | 10 |

Это ровно `gmsfem.fem.MATERIALS["notebook"]`. Случайные включения и случайные коэффициенты не используются. Коэффициенты сохраняются по ячейкам DG0; усреднённые узловые значения служат только входом SNO. В FEM-сборку идут точные ячеечные коэффициенты.

Падающая волна: uᶦ(x) = exp(ik d·x), d = (cosθ, sinθ). Решается рассеянное комплексное поле uˢ; полное поле u = uᶦ + uˢ. Оператор P1 FEM имеет вид **Kα − k²Mn − ikB**. Контрастная правая часть сохраняет интерфейсные вклады:

`∫ (1−α) ∇uᶦ·∇v̄ + k²(n−1)uᶦv̄`.

На внешней границе — поглощающее условие первого порядка. Эталон здесь численный: это решение P1 FEM с тем же приближённым граничным условием.

## Сетка и происхождение эталона

Для обучения и тестовых меток **копируется существующий файл** `gmsfem/meshes/reference_n20_h0p04.msh`: 53 246 неизвестных, 105 690 треугольников, эффективный h = 0.02. Новая сетка не генерируется.

SHA256: `9273efc7c0b500209ff847de4ee36d3790b93d64b09e67f62348318ed6b6cb47`.

Сетка GMsFEM — исходная тонкая сетка сохранённой таблицы: `gmsfem/meshes/fine_n20_h0p04.msh`, 17 549 неизвестных, 34 696 треугольников, h = 0.04.

SHA256: `a8af14fc965d4823fcb5be5d6f102e7225ff2d553b1c4b3a71325834e30807de`.

Перед генерацией проверяются контрольная сумма, координаты, порядок DOF и связность относительно `gmsfem/results/notebook/fields.npz`. Независимо решается k = 1, θ = 0 и сравнивается с сохранённым `reference_scattered`; результаты проверки записываются в `data/<band>/provenance.json`. Ускоренная сборка RHS пропускает ячейки с **точно нулевым контрастом** и проверяется против полной сборки при k = 1 и k = 4.

Таким образом, новая SNO учится непосредственно на более мелком FEM-эталоне; GMsFEM сохраняет исходные пространства своей таблицы. При сравнении оба поля интегрируются в точках квадратуры эталонной сетки. В ошибку GMsFEM входят редукция и дискретизация исходной тонкой сетки.

## Датасеты и отсутствие утечки

Для каждого диапазона задаются 160 равномерных частот и 8 направлений на частоту. В low дополнительно включается k = 1, если он не совпал с сеткой: **161 частота / 1288 полей**. В high: **160 частот / 1280 полей**.

Разбиение идёт **по частотам**, а не по отдельным направлениям. Все восемь полей одной частоты находятся только в одном split. Seed данных — 2026; доли train/validation/test — 0.67/0.17/остаток с округлением вниз первых двух количеств групп. Концы обоих диапазонов и вся группа k = 1 в low принудительно оставлены в test. При k = 1 есть θ = 0 для проверки старой таблицы. На остальных частотах восемь равномерных направлений получают воспроизводимый случайный угловой сдвиг.

| Диапазон | Train: частоты / поля | Validation | Test |
|---|---:|---:|---:|
| [0.1,2] | 107 / 856 | 27 / 216 | 27 / 216 |
| [2,4] | 107 / 856 | 27 / 216 | 26 / 208 |

POD-базисы и нормировки строятся только по train. Глобальный выходной ранг выбирается по validation; лучшая эпоха — также по validation. Test не используется для выбора настроек. Окончательная конфигурация одинакова для обоих диапазонов. По колебаниям validation в предварительном low-запуске добавлено снижение learning rate при плато; предварительный запуск остановлен до тестирования и сохранения checkpoint. Решение и настройки зафиксированы в `results/validation_decision.json` до запуска окончательных моделей. Поиск гиперпараметров по test не выполняется.

Обучаются **две отдельные модели**, каждая внутри своего диапазона. Дополнительно замороженная low-модель проверяется на test-частотах **k > 2** из high. Эта дополнительная проверка показывает экстраполяцию и не подменяет обучение high-модели. Общая граница k = 2 удержана в test обоих датасетов и исключена из строки экстраполяции.

Метки хранятся в `u_scat.npy` как complex128 с memory mapping; одна полоса занимает около 1.1 GB. Неизменные коэффициенты хранятся одной строкой и разворачиваются broadcast-представлением. После каждой частоты метки сбрасываются на диск и обновляется `completed.npy`: прерванную генерацию можно продолжить той же командой. Несовпадение конфигурации приводит к ошибке, а не к смешиванию данных.

## С чем сравнивается SNO

| Метод | Пространство / обучение |
|---|---|
| SVD-SNO v2 low | Обучение на train внутри [0.1,2], прогноз комплексного uˢ на 53 246 узлах |
| SVD-SNO v2 high | Независимое обучение внутри [2,4], та же архитектурная конфигурация |
| SNO low extrapolation | Замороженная первая модель на k > 2 без дообучения |
| GMsFEM 10×10, Type 1 / Type 2, M = 16 | По 16 локальных мод на крупную вершину, 1936 глобальных неизвестных |
| GMsFEM 20×20, Type 1 / Type 2, M = 16 | По 16 локальных мод на крупную вершину, 7056 глобальных неизвестных |

GMsFEM решает проекционную систему `Pᴴ A P c = Pᴴ f`; эталонное решение не служит входом редуцированного решателя. Type 1 использует эллиптические локальные продолжения, Type 2 — частотно-зависимые продолжения Гельмгольца. Пространства переиспользуются между направлениями при одном k; Type 2 пересчитывается для нового k. Число мод M = 16 у GMsFEM — **локальное**, поэтому его нельзя отождествлять с глобальным POD-рангом SNO.

Сохранённая старая таблица GMsFEM относится только к **k = 1, θ = 0**, а не ко всему интервалу. Новый код отдельно воспроизводит эту точку, сопоставляет с CSV старой серии и затем вычисляет новые строки по обоим диапазонам. Старые значения не выдаются за результаты частотного теста.

## Метрики

Основная сопоставимая метрика — относительная комплексная L²-ошибка в процентах: `100 ‖u_pred − u_ref‖ / ‖u_ref‖`. Она приводится **отдельно для полного и рассеянного поля**, с mean, p95 и max по одинаковым test-полям. В CSV также есть Re, Im, |u| и обе нормировки из GMsFEM.

Для полного поля падающая волна вычисляется аналитически в точках семиточечной квадратуры Dunavant. Модуль берётся **после комплексной интерполяции**. GMsFEM оценивается непосредственно из исходной fine-сетки в тех же точках эталонной квадратуры; промежуточная узловая перепроекция не добавляется.

Loss обучения — средняя относительная комплексная ошибка **рассеянного** P1-поля с согласованной матрицей масс. Она вычисляется точно в POD-координатах, включая остаток вне базиса. POD строится с lumped-весами, но итоговый loss и комплексная тестовая метрика используют согласованное интегрирование. Подробности в [MODEL.md](MODEL.md).

Старые `neural_operator` результаты на случайной среде с 3221 узлом и k∈[1,2] сюда не включены: у них другие коэффициенты и другая сетка.

## Контейнер: исправление и запуск

Docker daemon работает; при исходной проверке контейнер не был создан, а базовый образ не содержал PyTorch. Новый Dockerfile устанавливает нейросетевые зависимости **в тот же `/dolfinx-env/bin/python3`**, где находятся complex DOLFINx и PETSc. При проверке CPU-сборка Torch 2.15.0 конфликтовала с BLAS из FEM-образа (`undefined symbol: sbgemm_`). Закреплена совместимая **torch 2.9.1+cpu**; healthcheck проверяет одновременный импорт FEM и Torch, а также `PETSc.ScalarType = complex128`. Полный состав установленного окружения сохранён в `results/requirements.lock.txt`.

Все команды ниже выполняются **из корня репозитория**, без `mpirun`. Если базового локального образа ещё нет, сначала:

```bash
docker compose build dolfinx-complex
```

Поднять исправленное окружение:

```bash
docker compose -f compose.yaml -f experiments/reference_sno_gmsfem/compose.yaml up -d --build dolfinx-complex
docker compose ps
docker compose exec -T dolfinx-complex python3 -m experiments.reference_sno_gmsfem.run environment
```

Генерация, обучение, сравнение и отчёт:

```bash
docker compose exec -T dolfinx-complex python3 -m experiments.reference_sno_gmsfem.run data --band low
docker compose exec -T -e OPENBLAS_NUM_THREADS=2 -e OMP_NUM_THREADS=2 dolfinx-complex python3 -m experiments.reference_sno_gmsfem.run train --band low
docker compose exec -T dolfinx-complex python3 -m experiments.reference_sno_gmsfem.run baselines --band low

docker compose exec -T dolfinx-complex python3 -m experiments.reference_sno_gmsfem.run data --band high
docker compose exec -T -e OPENBLAS_NUM_THREADS=2 -e OMP_NUM_THREADS=2 dolfinx-complex python3 -m experiments.reference_sno_gmsfem.run train --band high
docker compose exec -T dolfinx-complex python3 -m experiments.reference_sno_gmsfem.run baselines --band high
docker compose exec -T dolfinx-complex python3 -m experiments.reference_sno_gmsfem.run extrapolate
docker compose exec -T dolfinx-complex python3 -m experiments.reference_sno_gmsfem.run report
```

Этапы разделены, чтобы освобождать память между двумя большими датасетами. Обычный повтор обучения загружает уже завершённый совместимый checkpoint. Изменение настроек требует нового каталога либо осознанного переноса прежних артефактов: скрытого перезаписывания несовместимых результатов нет.

Проверки:

```bash
docker compose exec -T dolfinx-complex python3 -m pytest experiments/reference_sno_gmsfem/tests -q
docker compose exec -T dolfinx-complex python3 -m pytest neural_operator/tests/test_operators.py neural_operator/tests/test_pod_fem_loss.py -q
```

## Файлы и границы выводов

- `dataset.py` — точная сетка/среда, генерация, возобновление, контроль происхождения.
- `baselines.py` — GMsFEM, межсеточная квадратура и проверка исходной таблицы.
- `run.py` — этапы запуска, SNO, экстраполяция и итоговый отчёт.
- `training.py` — локальный цикл обучения с уменьшением шага по validation; исторический training-код проекта не меняется.
- `MODEL.md` — архитектура, формулы, гиперпараметры и смысл рангов.
- `data/{low,high}` — локальные метки, split и provenance; исключены из Git.
- `runs/{low,high}` — checkpoints и полные предсказания; исключены из Git.
- `results/` — компактные CSV/JSON, графики, отчёт и версии окружения.

Это проверка по частоте и направлению **в одной фиксированной среде**, а не перенос на новые материалы. При постоянных α и n входные POD-ранги материала равны нулю: модель фактически учит отображение `(k,θ) → uˢ` для этой среды. Сравнение показывает качество выбранных пространств и обучения, но не равный вычислительный бюджет методов. Генерация меток, подготовка POD, обучение, offline-построение GMsFEM и online-решение учитываются раздельно. Один seed не позволяет судить о разбросе между независимыми обучениями. Эталонный FEM имеет собственную ошибку дискретизации.

Локальное обучение использует AdamW с начальным шагом 0.002 и снижением
шага `ReduceLROnPlateau` по validation: factor=0.5, patience=20,
relative threshold=0.001, min_lr=1e-5. Политика зафиксирована после
наблюдения колебаний train/validation при постоянном шаге и до выбора
по test. Подбор гиперпараметров и выбор checkpoint по test не выполняются.
Полные параметры и формулы приведены в [MODEL.md](MODEL.md).
