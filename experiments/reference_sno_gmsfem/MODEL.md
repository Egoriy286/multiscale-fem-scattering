выше decoder floor: дальнейшее увеличение POD-ранга само по себе
не устраняет ошибку отображения параметров волны в коэффициенты.
Обучение завершено по лимиту эпох, а не по доказанной сходимости к
лучшему возможному результату SNO. Все сравнения относятся к этим
конкретным checkpoint. Полное поле и GMsFEM: [отчёт](results/REPORT.md).

Здесь используется **SVD-SNO версии 2** из `neural_operator/sno/model.py`.
Это нейронная модель в пространстве коэффициентов POD. Она предсказывает
комплексное рассеянное поле на той же FEM reference-сетке, на которой
сохранён независимый эталон таблицы GMsFEM. Предсказываются Re и Im;
модуль вычисляется после восстановления поля:

\[
u_s=u_R+i u_I,\qquad |u_s|=\sqrt{u_R^2+u_I^2}.
\]

Полное поле для сопоставления с таблицей восстанавливается как
\(u_{total}=\exp(ik(\cos\theta,\sin\theta)\cdot x)+u_s\).
Нельзя напрямую сопоставлять относительную ошибку рассеянного поля
с ошибкой полного поля: у них разные знаменатели.

## Физическая задача и границы утверждений

Во всей выборке фиксированы геометрия, сетка и материал preset `notebook`:
фон \(A=I,n=1\), все 24 включения \(A=0.2I,n=10\). Источник значений —
`gmsfem.fem.MATERIALS['notebook']`; это **не** случайная среда прежнего
static-low опыта. Сохраняется исходная маркировка материалов 1/2/3/4.

Берётся существующий `gmsfem/meshes/reference_n20_h0p04.msh`: фактический
целевой шаг 0.02, 53 246 узлов и 105 690 треугольников. Имя содержит
0p04, потому что reference-сетка была построена с половинным шагом
от основной сетки таблицы. SHA256:

```
9273efc7c0b500209ff847de4ee36d3790b93d64b09e67f62348318ed6b6cb47
```

Меняются только \(k\) и направление падающей плоской волны \(\theta\).
Поэтому этот опыт проверяет интерполяцию по волновым параметрам **одной
среды** и отдельный частотный перенос. Он не проверяет неизвестные
материалы, число включений или новые геометрии. Reference — дискретное
P1-решение; ошибка относительно него не является доказанной ошибкой
относительно непрерывной PDE.

## Выборки и защищённая точка таблицы

Создаются два независимых набора и две отдельно обученные модели:

| Набор | Диапазон k | Смысл основной проверки |
|---|---|---|
| low | [0.1, 2] | Удержанные частоты той же среды |
| high | [2, 4] | Удержанные частоты high при отдельном обучении |

Замороженная модель low дополнительно проверяется на high при **k>2**.
Точка k=2 принадлежит обоим диапазонам и зарезервирована в test обоих
наборов. Она не считается проверкой вне диапазона low.

Параметр `n_frequencies=160` задаёт равномерную сетку k. Если она не
содержит k=1, в low добавляется отдельная частотная группа k=1. Поэтому
по умолчанию low имеет **161×8=1288** полей, high — **160×8=1280**.
Все направления одной частоты остаются в одном split. Граничные частоты
диапазона и вся low-группа k=1 принудительно принадлежат test. В группе
k=1 первое направление имеет theta=0, точно как в таблице GMsFEM.

Для остальных групп используется перестановка с seed=2026. Число train
равно floor(0.67×число групп), validation — floor(0.17×число групп),
остаток относится к test. Для стандартного размера получаются:

| Набор | Train групп/полей | Validation групп/полей | Test групп/полей |
|---|---|---|---|
| low | 107 / 856 | 27 / 216 | 27 / 216 |
| high | 107 / 856 | 27 / 216 | 26 / 208 |

У остальных частот восемь равномерно разнесённых углов с воспроизводимым
случайным offset. Для каждой частоты генератор LU-факторизует оператор
один раз и использует его для всех направлений.

## POD: пространственные формы и коэффициенты

По **train** отдельно строятся средние и пространственные POD-моды
действительной и мнимой частей. Для компоненты f:

\[
f(x)\approx\mu_f(x)+\sum_{j=1}^{r_f}c_{f,j}\phi_{f,j}(x).
\]

Взвешенная SVD использует положительные lumped FEM-массы узлов. Если
\(W=\mathrm{diag}(w)\), то для центрированной матрицы train-снимков X:

\[
XW^{1/2}=U\Sigma V^T,\qquad\Phi=W^{-1/2}V_r,
\quad c=(f-\mu)^TW\Phi.
\]

`pod_method='randomized'` ограничивает стоимость вычисления ведущих мод.
В текущем алгоритме используются oversampling=10, две power-итерации
с QR и seed модели. Результат остаётся приближённой SVD, а не новым
нейросетевым слоем. Выходные Re/Im базисы различны; номера их мод не
означают одну и ту же пространственную функцию.

Максимальный ранг выбран **96**. Предобработка перебирает ранги от 1 до
доступного максимума и выбирает первый, для которого средняя complex
consistent FEM L2 ошибка POD-reconstruction на validation не больше
**0.001 = 0.1%**. Если порог недостижим, остаётся максимальный доступный
ранг и в метриках записывается `rank_target_attained=false`.

Этот порог относится к decoder и среднему по validation, а не к будущей
ошибке сети или p95. Ранг выбирается по reconstruction через lumped POD
encode; дополнительно отчёт сохраняет минимально достижимый floor для
того же decoder в **consistent** массе. Эти две величины близки, но в
общем случае различаются. При большом floor сначала нужно увеличить
выходное пространство, а затем рассматривать глубину сети.

Материал одинаков во всех снимках. Его центрированные входные POD-ранги
равны нулю: модель фактически получает три глобальных признака
\(\cos\theta,\sin\theta,\widetilde k\), где k нормируется по train.
Сохранение A/n в данных необходимо для точной постановки и физических
проверок, однако это обучение не учит сеть реагировать на новую среду.

## Архитектура SNO v2

При общем выходном размере r каждая модальная позиция сначала получает
пятикомпонентный token:

\[
t_j=[0,0,\cos\theta,\sin\theta,\widetilde k],\quad
Z^{(0)}_j=\mathrm{GELU}(L_{5\to H}(t_j)).
\]

Нули — отсутствующие изменяющиеся коэффициенты A/n. В общем API вместо
них подаются независимые последовательности входных POD-коэффициентов
материала с дополнением нулями. Размер таблицы скрытых признаков —
`[batch, r, H]`, здесь **H=48**.

Далее следуют **6 residual-блоков**. Каждый вычисляет параллельную сумму
локальной ветви и смешивания мод:

\[
Z' = Z+\mathrm{GELU}\bigl(ZW_{local}+b+BZW_{channel}\bigr).
\]

`W_local` и `W_channel` смешивают каналы; обучаемая матрица B смешивает
позиции мод. После последнего блока линейная проекция H→2 возвращает
нормированные коэффициенты Re и Im. Затем применяются train-only
обратная нормировка, POD-decoder и добавление среднего поля. У этой
версии нет FFT и свёртки на регулярной пространственной решётке.

Для r выходных позиций и фиксированной среды число вещественных
параметров равно:

\[
P=8H+2+L(2H^2+H+r^2)=28322+6r^2
\]

при H=48,L=6. Для максимального r=96 это **83 618 параметров**; фактический
размер берётся из обученного checkpoint. Эта конфигурация — осмысленная
начальная настройка для более широкого диапазона k. Один run не является
ablation-доказательством, что глубина 6 лучше глубины 3 или 12.

Это число считает только обучаемые веса сети. Средние поля, две таблицы
POD-мод размером примерно 53 246×r и координаты тоже занимают память,
но не обучаются градиентным методом и в этот счётчик не входят.
Число параметров SNO нельзя напрямую приравнивать к числу неизвестных
линейной системы GMsFEM: там 16 мод на каждую крупную вершину дают
1936 либо 7056 коэффициентов **на одно решаемое поле**.

## Оптимизация и выбор checkpoint

| Параметр | Начальное значение | Назначение |
|---|---|---|
| Максимум эпох | 500 | Верхняя граница проходов по train |
| Batch size | 32 | Число решений в одном шаге optimizer |
| AdamW learning rate | 0.002 | Шаг обновления параметров |
| Weight decay | 0.00001 | Регуляризация весов |
| AdamW betas | (0.9, 0.999) | Экспоненциальные моменты градиента |
| AdamW eps / amsgrad | 1e-8 / false | Численная стабилизация и стандартный AdamW |
| Gradient clip norm | 1 | Ограничение нормы градиента |
| Минимум эпох | 150 | Ранняя остановка до этого не срабатывает |
| Patience | 100 | Остановка после 100 эпох без улучшения val |
| Model/POD seed | 42 | Воспроизводимые веса, batches и randomized POD |
| Torch threads | 2 | CPU-параллелизм обучения |
| LR scheduler factor | 0.5 | Уменьшение шага вдвое при плато validation |
| LR scheduler patience | 20 | Допустимое число эпох без существенного улучшения |
| Минимальный learning rate | 0.00001 | Нижняя граница шага AdamW |

У scheduler `cooldown=0`, `eps=1e-8`; threshold mode — relative,
threshold — 0.001. Dropout и batch normalization в SNO отсутствуют.

Локальный `training.py` использует `ReduceLROnPlateau(mode='min')`.
После каждой validation-проверки scheduler ищет относительное улучшение
не меньше 0.1% (`threshold=0.001`, `threshold_mode='rel'`). После 20
допустимых эпох без такого улучшения следующий плохой epoch уменьшает
learning rate вдвое, до нижней границы 1e-5. В `history['lr']` записан
шаг, который использовался **в этой эпохе**; scheduler выбирает шаг для
следующей. В checkpoint-метаданных и `metrics.json` сохраняются настройки
scheduler и конечный шаг optimizer. Resume optimizer по-прежнему отсутствует.

Это изменение принято по колебаниям train и validation при начальном
постоянном шаге 0.002, до выбора модели по test. Других гиперпараметров
по test не подбирают. Полная конфигурация, включая scheduler, должна
совпадать для повторного использования готового run; старый fixed-rate
checkpoint не получает scheduler задним числом.

Лучший checkpoint
выбирается по validation loss; при остановке восстанавливаются его веса.
Test оценивается после fit. При анализе результатов нельзя подбирать
настройки по строке k=1 или другим test-ошибкам и затем называть тот же
test независимой финальной проверкой.

Loss — среднее **относительных комплексных FEM L2 норм по примерам**:

\[
\mathcal L=\frac1B\sum_s\sqrt{
\frac{(\widehat u_s-u_s)^H M(\widehat u_s-u_s)}{u_s^HMu_s}}.
\]

M — consistent P1 mass matrix; интегрирование не заменяется обычным
средним по узлам. Для SNO та же форма заранее сворачивается в небольшие
Gram-матрицы выходных POD-мод, поэтому обучение зависит главным образом
от ранга, а не от 53 тысяч узлов. Предвычисление работает в float64,
сеть — float32. Сохраняется irreducible residual decoder, поэтому сеть
не получает искусственно заниженный loss из-за усечения базиса.

## Данные на диске, возобновление и физическая проверка

`dataset.generate_dataset(path, band='low'|'high', ...)` принимает путь
**одного** набора, например `data/low`. `load_dataset(path)` возвращает
стандартный `neural_operator.data.Dataset`, но читает собственный формат
этого эксперимента:

| Файл | Содержание |
|---|---|
| config.json | Точный рецепт; несовпадение запрещает reuse |
| etal.msh | Копия существующей reference-сетки с проверкой SHA256 |
| reference_problem.npz | Сетка, DG0/nodal материалы по одной строке, anchor |
| samples.npz | Все k,theta,frequency_id,medium_id,split |
| u_scat.npy | Несжатые complex128 labels; read-only mmap при загрузке |
| completed.npy | Флаг завершения каждой частотной группы |
| provenance.json | Происхождение, SHA256 источников, проверка anchor/RHS |
| dataset_info.json | Признак полного завершения, размеры и хеши файлов |

Материалы не повторяются для каждого поля: при загрузке используются
read-only broadcast views. NPY labels не распаковываются во второй cache.
Частотная группа считается готовой после записи всех её направлений
и `flush`; bitmap заменяется атомарно. После прерывания завершённые
группы используются повторно, незавершённая группа пересчитывается.
Неполный набор нельзя открыть как готовый Dataset. Автоматического
продолжения optimizer после прерывания обучения в общем training API нет.

Перед генерацией проверяются SHA256 mesh, число узлов/элементов,
точное совпадение connectivity и порядка DOF с
`gmsfem/results/notebook/fields.npz`. Новый FEM solve k=1,theta=0 сравнивается
со `reference_scattered` в consistent FEM L2; порог 1e-6, нормированный
линейный residual не выше 1e-8. Фактические значения сохраняются.

В правой части аналитическая падающая волна вычисляется только в 4490
элементах с ненулевым контрастом: остальные дают точно нулевой вклад.
Квадратура 8×8 Duffy и формулы исходного solver сохранены. Перед
использованием оптимизированная RHS сравнивается с полной на k=1 и k=4;
относительное различие должно быть не больше 1e-12. Это ускоряет
генерацию, не меняя дискретную постановку.

При чтении проверяются малые файлы геометрии/метаданных по SHA256,
completion bitmap, форма и конечность полей. Полный SHA256 `u_scat.npy`
сохраняется при завершении генерации и доступен для отдельного аудита;
повторная загрузка не перечитывает labels второй раз только ради хеша.

Один набор стандартного размера занимает примерно **1.10 GB** raw
complex128 labels. POD делает дополнительные dense временные копии
train-компонент: даже mmap не устраняет рабочую память SVD. Два набора
нужно генерировать и обучать последовательно, измеряя фактическую память
и время. Прогноз скорости не заменяет сохранённые wall-clock измерения.
