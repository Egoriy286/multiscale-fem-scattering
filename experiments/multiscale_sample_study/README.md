Сравниваются обычные SVD-SNO/FNO и их multiscale-варианты на **400, 600, 800 и 1000 train-примерах**. Общие validation/test содержат по 100 других физических частот. Всего заново решены 1200 FEM-задач на 53 246 узлах; новые метки не получены интерполяцией старых решений. Train-наборы вложены, каждый запуск начинается с новых весов. Четыре метода × четыре размера × три seeds = 48 запусков.

Один sample — одно комплексное рассеянное поле при одном k в [0.1,4], на фиксированной notebook-среде и при theta=0. Частотные ID, параметры, splits и SHA256 сохранены в `data/samples.npz`, `data/config.json`, `data/dataset_info.json`. Общее количество полей в конкретном запуске — 600/800/1000/1200. Случай 800/100/100 совпадает с двумерным примером MscaleFNO по числам, но статья меняет случайную среду, а здесь меняется частота. Это проверка интерполяции для одной среды.

Основная метрика для **обучения, validation и test всех четырёх методов**:

$$100\sqrt{(\hat u-u)^*M(\hat u-u)/(u^*Mu)}.$$

Это относительная комплексная L2-норма рассеянного P1-поля с полной согласованной матрицей масс. Усреднение производится после вычисления относительной нормы каждого случая. Для полного поля отдельно используется аналитическая падающая волна в квадратурных точках. POD и нормировки строятся по соответствующему train-префиксу; выходы FNO переносятся на FEM-сетку. Проекционные остатки входят в loss. Checkpoint выбирается только по validation; test не выбирает архитектуру, ранг или эпоху.

[Полный протокол](PROTOCOL.md) · [Сопоставление со статьями](ARTICLE_COMPARISON.md) · [Зафиксированные настройки](protocol.json).

Бюджет этой серии — **100 эпох**, Adam/cosine, batch 50, evaluation на первой, каждой пятой и последней эпохе, 15 проверок без улучшения для early stopping. В статье MscaleFNO было 500 эпох и значительно более крупные модели на RTX 4090. Здесь FFT-сетка 64×64, восемь мод, четыре блока; восемь ветвей ширины 2 сравниваются с обычной FNO ширины 6. SVD-SNO использует запрошенный комплексный POD-ранг 20, multiscale-ширину 8 и близкое число параметров у обычного варианта. Эти изменения явно ограничивают выводы; лимит эпох сам по себе не доказывает сходимость.

SNO работают на CPU с двумя потоками, FNO — на MPS этого Mac. Внутри каждой обычной/multiscale-пары backend общий. Сравнение wall time между разными семействами включает разницу backend. Online вычисления используют float32 там, где это требуется MPS; validation и финальная FEM-оценка — float64. Linux Docker используется для complex FEM-генерации и GMsFEM baseline; его версии записаны в [generation_environment.json](results/generation_environment.json). Для воспроизводимости сохранённый `samples.npz` является источником точных частот: последние биты заново вычисленного планировщика могут зависеть от версии NumPy.

Из корня проекта:

```bash
make sample-data       # Docker: подготовить/проверить FEM-метки
make sample-study      # native macOS: обучение, replay, независимый аудит, отчёт
make sample-status
```

Все 48 запусков и повторная проверка checkpoints завершены. [Итоговый отчёт](results/REPORT.md) · [Статус выполнения](results/execution.json).

Для нового запуска команда `python -m experiments.multiscale_sample_study.run live` строит промежуточные кривые локально. При изменении настроек используйте новый `--root` и отдельный протокол. Для независимого теста после подбора по опубликованным результатам также нужны новый seed планировщика и новый manifest. Во время обучения состояние optimizer/scheduler/RNG и лучший checkpoint сохраняются на evaluation-эпохах. После прерывания повторяются только несохранённые эпохи.
