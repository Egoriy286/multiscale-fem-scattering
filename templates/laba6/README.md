# Лабораторная 6

Оба скрипта, `lr6.py` (DOLFINx) и `lr6_legacy.py` (DOLFIN 2019), используют
геометрию `../laba4/mesh.geo`: квадрат 1×1,
разбитый линиями Gmsh на 10×10 крупных квадратов. Внутри строится согласованная
мелкая треугольная сетка с шагом примерно `h = 1/(n*fine)`.
`--fine` по умолчанию равен 4; `n` читается из существующего `mesh.geo`.

Вокруг каждой вершины A собираются соседние крупные квадраты: четыре внутри
области, два на стороне, один в углу. Получается 121 окрестность. Они
перекрываются: каждый крупный квадрат входит в четыре окрестности.

Внешняя граница каждой окрестности имеет метку **1**. Её составляющие квадраты
сохраняются отдельно, с метками границ по рисунку задания:

- **1** — вертикальная сторона, проходящая через A (`x = A_x`);
- **2** — горизонтальная сторона, проходящая через A (`y = A_y`);
- **3** — две остальные стороны.

Разметка определяется по координатам в Python. В варианте DOLFINx в Gmsh
задаётся одна общая физическая группа для импорта всей сетки.
Лабораторная 6 строит сетки и разметку; спектральные задачи и базис GMsFEM
относятся к следующим этапам.

## Как устроен `lr6.py` (DOLFINx)

1. `ArgumentParser` читает плотность сетки и каталог результатов. Gmsh открывает
   существующую геометрию, строит треугольники и передаёт сетку `msh` в DOLFINx.
2. Массив `cells` содержит индексы треугольников, `numbers` — номер крупного
   квадрата для каждого треугольника. Объект `blocks` хранит эту разметку.
3. Два цикла перебирают вершины `(i, j)`. Список `neighbors` содержит номера
   соседних квадратов. `create_submesh` выделяет их объединение `omega`,
   затем каждый составляющий квадрат `part` из исходной мелкой сетки.
4. `boundary_tags` берёт только внешние рёбра подсетки. Без аргумента `vertex`
   она ставит метку 1; с координатами A назначает метки 1, 2, 3 по серединам рёбер.
5. `save` записывает сетку и метки. Все подсетки сразу сохраняются на диск;
   в списке `example` остаются только четыре квадрата центральной окрестности
   для рисунка. `LineCollection` показывает реальные помеченные рёбра.

## Запуск DOLFINx

Из корня проекта, в уже настроенном контейнере DOLFINx Complex:

```bash
docker compose exec dolfinx-complex python3 templates/laba6/lr6.py
```

Более мелкая сетка, с плотностью как в лабораторной 4:

```bash
docker compose exec dolfinx-complex python3 templates/laba6/lr6.py --fine 12
```

Скрипт работает в одном MPI-процессе. В терминале контейнера достаточно
`python3 templates/laba6/lr6.py`. Параметр `--output PATH` меняет каталог результатов.

## Результаты DOLFINx

- `results/mesh.xdmf` — вся мелкая сетка, метки `blocks` — номера крупных квадратов;
- `results/mesh.png` — вся сетка и пример окрестности с цветами меток;
- `results/omega_XXX/omega.xdmf` — окрестность и метки `boundary` её внешней границы;
- `results/omega_XXX/cell_YYY.xdmf` — каждый составляющий квадрат с локальными метками `boundary`.

Номер вершины `XXX = i + (n+1)*j`, координаты A — `(i/n, j/n)`.
Номер квадрата `YYY = p + n*q`, его левый нижний угол — `(p/n, q/n)`.
Квадрат сохраняется для каждой содержащей его окрестности: всего 400 файлов
ячеек, поскольку метки 1 и 2 зависят от выбранной вершины A.

Каждый XDMF содержит сетку и метки в одном файле (ASCII); отдельные HDF5-файлы
не требуются. Результаты можно открыть в ParaView или прочитать через
`dolfinx.io.XDMFFile`. При чтении также укажите
`encoding=io.XDMFFile.Encoding.ASCII`, иначе DOLFINx будет искать файл `.h5`.
Для чтения меток `boundary` после `read_mesh()` создайте связность
`msh.topology.create_connectivity(1, 2)` и вызовите
`file.read_meshtags(msh, name='boundary')`.

## Вариант DOLFIN 2019: последовательности для ParaView

`lr6_legacy.py` строит ту же геометрию и разметку через классический DOLFIN.
Как в лабораторной 4, Gmsh → Meshio → временный XML → `Mesh`.
`blocks` хранит номера крупных квадратов. `SubMesh` выделяет 100 квадратов
один раз, а затем — их объединения вокруг вершин. `boundary_tags` отмечает
внешние рёбра через `AutoSubDomain` и назначает квадратам метки относительно A.
В списках `submeshes` и `cell_submeshes` хранятся пары `(сетка, метки границы)`.

Запуск из корня проекта в уже имеющемся локальном образе Legacy
(проверено с DOLFIN `2019.2.0.dev0`):

```bash
docker run --rm --init -e OMP_NUM_THREADS=1 -e OPENBLAS_NUM_THREADS=1 \
  -v "$PWD":/workspace -w /workspace mvt25/fenics-legacy:local \
  python3 templates/laba6/lr6_legacy.py
```

В окружении с установленным DOLFIN 2019 достаточно
`python3 templates/laba6/lr6_legacy.py`. Параметры `--fine`, `--output` и ограничение
одним MPI-процессом такие же, как у DOLFINx.

Все результаты лежат в общей папке `results_legacy`, без подкаталогов.
Для `n=10` получаются следующие последовательности:

| Файл | Что показывает | Кадры / псевдовремя |
| --- | --- | --- |
| `blocks.pvd` | Вся сетка и номера крупных квадратов | Один кадр |
| `neighborhoods.pvd` | Треугольные сетки окрестностей | 0–120 |
| `neighborhood_boundaries.pvd` | Метки рёбер тех же окрестностей | 0–120 |
| `cells.pvd` | Составляющие квадратные подсетки | 0–399 |
| `cell_boundaries.pvd` | Метки рёбер тех же квадратов | 0–399 |

В ParaView откройте нужный PVD и нажмите **Apply**, затем переключайте время.
Это индекс подсетки, а не физическое время. Сетки и метки разной размерности
записаны отдельно: у каждой пары PVD совпадают номера кадров. У рёбер метка
**0** означает внутреннее ребро мелкой сетки; **Threshold > 0** оставляет границу.
Для просмотра окрестностей открывайте пару `neighborhoods` / `neighborhood_boundaries`,
для просмотра квадратов — пару `cells` / `cell_boundaries`: у этих двух пар разные шкалы.
Данные кадров находятся в соседних `.vtu`: PVD ссылается на них, поэтому
переносите всю папку результатов вместе.

Порядок окрестностей: сначала растёт `i` (вдоль x), затем `j` (вдоль y);
кадр `vertex = i + (n+1)*j`. Внутри каждой окрестности квадраты идут
снизу вверх, слева направо. `cells.csv` связывает кадр квадрата `frame`
с номером вершины `vertex` и исходного квадрата `block = p + n*q`.
Вершина A имеет координаты `(i/n, j/n)`; левый нижний угол квадрата — `(p/n, q/n)`.
